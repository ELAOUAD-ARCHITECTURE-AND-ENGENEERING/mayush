# 2. ADN Visuel de Mayush Design

Mayush Design doit transmettre une image :

- Premium
- Élégante
- Chaleureuse
- Contemporaine
- Inspirée par Marrakech et l’artisanat marocain
- Adaptée à une marketplace de mobilier et décoration
- Lisible, accessible et mobile-first

## Principes fondamentaux

- **Minimalisme contemporain :** design épuré, touches marocaines subtiles.
- **Élégance intemporelle :** sensation premium, professionnelle et raffinée.
- **Cohérence visuelle :** même logique graphique sur homepage, blog, catégories, produits, vendeurs et checkout.
- **Chaleur sophistiquée :** orange terre cuite, beige clair, noir profond.
- **Accessibilité :** contraste lisible, tailles de texte correctes, états interactifs visibles.
- **Responsive mobile-first :** interface fluide sur mobile, tablette et desktop.

# 3. Typographie

La typographie est l’un des éléments les plus importants de l’identité Mayush Design. Elle doit créer une hiérarchie claire entre les titres éditoriaux, les textes commerciaux, les descriptions produits et les boutons.

## 3.1 Police principale

**Police recommandée :**

- Playfair Display
- Alternative : Cormorant Garamond

**Utilisation :**

- Titres principaux
- H1
- H2
- Titres de sections
- Accroches premium
- Titres éditoriaux du blog
- Titres de collections

**Style recherché :**

- Élégant
- Haut de gamme
- Editorial
- Raffiné
- Inspiré magazine déco/lifestyle

## 3.2 Police secondaire

**Police recommandée :**

- Inter
- Alternatives : Poppins, Montserrat

**Utilisation :**

- Paragraphes
- Descriptions produits
- Boutons
- Labels
- Menus
- Filtres
- Textes secondaires
- Interface admin/frontend

**Style recherché :**

- Clair
- Moderne
- Lisible
- Fonctionnel
- Adapté à l’e-commerce

# 8. Boutons

Les boutons doivent être clairs, élégants et immédiatement identifiables. Le bouton primaire doit être réservé aux actions prioritaires.

## 8.1 Bouton primaire

**Usage :**

- Ajouter au panier
- Explorer la marketplace
- Voir les offres du jour
- S’inscrire
- Découvrir une collection
- Valider une commande

```css
.btn-primary {
  background: #D97434;
  color: #FFFFFF;
  padding: 14px 32px;
  border-radius: 6px;
  border: none;
  font-family: 'Inter', sans-serif;
  font-size: 16px;
  font-weight: 600;

}

.btn-primary:hover {
  background: #C46524;
  transform: translateY(-2px);

}
```

**Exemples de texte :**

- Découvrir nos meubles
- Ajouter au panier
- Explorer la marketplace
- Voir les offres
- Consulter le blog

**Usage :**

# 9. Cartes

Les cartes sont utilisées pour les articles de blog, produits, collections, vendeurs, catégories et inspirations.

## 9.1 Carte standard

```css
.card {
  background: #FFFFFF;
  border: 1px solid #E5E0D8;
  border-radius: 8px;
  overflow: hidden;
  box-shadow: 0 2px 8px rgba(0, 0, 0, 0.08);
  transition: all 0.3s ease;
}

.card:hover {
  transform: translateY(-4px);
  box-shadow: 0 8px 24px rgba(0, 0, 0, 0.12);
}

.card-content {
  padding: 24px;
}
```

## 9.2 Structure recommandée

Une carte éditoriale doit contenir :

- Image premium
- Tag ou catégorie
- Titre
- Description courte
- CTA discret

Une carte produit marketplace doit contenir :

- Image produit claire
- Nom produit
- Marque ou vendeur
- Badge vendeur vérifié
- Rating
- Prix actuel
- Ancien prix si promotion
- Badge livraison
- Wishlist
- CTA panier ou quick view

## 9.3 Tags de carte

```css
.card-tag {
```

Le système de layout repose sur une grille flexible de 12 colonnes.

## 10.1 Grille 12 colonnes

```css
.grid-12 {
  display: grid;
  grid-template-columns: repeat(12, 1fr);
  gap: 20px;
}
```

## 10.2 Largeurs recommandées

| Type | Colonnes | Usage |
|---|---:|---|
| Full width | 12/12 | Hero, sections pleine largeur |
| Half width | 6/12 | Deux colonnes, texte + image |
| Third | 4/12 | Cartes en 3 colonnes |
| Quarter | 3/12 | Catégories, petits blocs |

## 10.3 Espacements standards

| Élément | Valeur recommandée |
|---|---:|

| Padding cartes | 24px |
| Marges horizontales desktop | 40px à 60px |
| Container max-width | 1200px |
| Gap cartes | 30px |

# 13. Accessibilité

L’accessibilité est une règle de base pour Mayush Design.

## 13.1 Standards

- Respect WCAG 2.1 niveau AA
- Contraste minimum 4.5:1 pour les textes
- Texte corps minimum 16px
- Navigation claire
- Structure sémantique
- États focus visibles
- Interface mobile lisible

## 13.2 Règles pratiques

- Ne jamais utiliser du texte orange petit sur fond blanc si le contraste est insuffisant.
- Toujours garder un état `:focus` visible sur boutons, liens et inputs.
- Ne jamais descendre sous 16px pour un texte principal.
- Ne pas masquer les contenus SEO importants.
- Prévoir des textes alternatifs pour les images.
- Garder une hiérarchie H1/H2/H3 propre.

## 13.3 Focus state recommandé

```css
a:focus,
button:focus,
input:focus,
select:focus,
textarea:focus {
  outline: 2px solid #D97434;
  outline-offset: 3px;
}
```

# 14. Responsive Design

Mayush Design doit être mobile-first.

## 14.1 Breakpoint principal

```css
@media (max-width: 768px) {
  .header h1 {
    font-size: 36px;
  }

  .header .subtitle {
    font-size: 24px;
  }

  h2 {
    font-size: 32px;
  }

  .container {
    padding: 40px 20px;
  }

  .grid-12 {
    gap: 10px;
  }

  .grid-item {
    grid-column: span 12;
  }
}
```

## 14.2 Règles mobile

- Les grilles deviennent une colonne.
- Les cartes gardent un padding confortable.
- La navigation doit rester simple.
- Les boutons doivent être faciles à cliquer.
- Les images doivent se charger rapidement.
- Éviter tout overflow horizontal.
- Prioriser recherche, catégories, panier et compte.

# 17. Checklist d’Implémentation Frontend

Utiliser cette checklist avant validation d’une nouvelle page Mayush.

## Typographie

- [ ] Un seul H1 par page.
- [ ] H1 en Playfair Display ou Cormorant Garamond.
- [ ] H2 cohérents et visibles.
- [ ] Texte principal minimum 16px.
- [ ] Inter/Poppins/Montserrat utilisé pour les textes d’interface.

## Couleurs

- [ ] Orange `#D97434` réservé aux CTA et accents.
- [ ] Noir `#1A1A1A` utilisé pour titres principaux.
- [ ] Beige `#F5F1E8` utilisé pour sections douces.
- [ ] Gris `#8B8B8B` utilisé pour contenu secondaire.
- [ ] Pas de mélange non contrôlé avec d’autres couleurs.

## Composants

- [ ] Boutons primaires cohérents.
- [ ] Boutons secondaires cohérents.
- [ ] Cards avec border-radius 8px.
- [ ] Cards avec hover subtil.
- [ ] Badges/tags uniformes.

## Layout

- [ ] Container max-width autour de 1200px.
- [ ] Sections bien espacées.
- [ ] Grille responsive.
- [ ] Aucun overflow horizontal.
- [ ] Mobile testé.

## Imagerie

- [ ] Images premium et cohérentes.
- [ ] Images optimisées.
- [ ] Alt text présent.
- [ ] Ratio image cohérent pour cartes.
- [ ] Pas de placeholders gris pauvres.

## Accessibilité

- [ ] Contraste suffisant.
- [ ] Focus states visibles.
- [ ] Structure H1/H2/H3 correcte.
- [ ] Navigation clavier possible.
